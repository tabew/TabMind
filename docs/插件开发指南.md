# 插件开发指南

## 一、加载机制

机器人启动时扫描运行目录下的 `plugins\` 文件夹，对每个 `.dll`：

1. `LoadLibrary` 加载
2. 取 `create_plugin` 函数指针，调用得到 `IBotPlugin*` 实例
3. 调用 `on_load()`，读取 `get_info()` 元数据并显示在界面「插件管理」里
4. 之后每条消息按加载顺序派发到 `on_message`

退出或卸载时调用 `on_unload()`，再用 `destroy_plugin` 释放实例。

> DLL 必须导出 **`create_plugin`** 与 **`destroy_plugin`** 两个 `extern "C"` 函数，否则不会被识别。

## 二、接口定义

全部定义在 `include/plugin_manager.hpp`（插件只需包含该头文件）。

```cpp
class IBotPlugin {
public:
    virtual ~IBotPlugin() = default;

    virtual PluginInfo get_info() = 0;      // 元数据：名称/版本/作者/简介
    virtual bool on_load() = 0;             // 返回 false 视为加载失败
    virtual void on_unload() = 0;

    // 消息前置处理
    //   返回 true  已处理，主程序不再调用 AI（不消耗 Token）
    //   返回 false 未处理，继续交给 AI
    virtual bool on_message(const PluginContext& ctx) = 0;

    // AI 生成回复后、发送前的钩子（可改写/追加内容，如附带表情）
    virtual void on_ai_reply(const PluginContext& ctx, std::string& ai_reply_text) {}
};
```

### PluginContext 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `message_type` | `std::string` | `"private"` 或 `"group"` |
| `user_id` | `int64_t` | 发送者 QQ |
| `group_id` | `int64_t` | 群号（私聊为 0） |
| `sender_name` | `std::string` | 群名片或昵称 |
| `at_user_ids` | `std::vector<int64_t>` | 本条消息 @ 到的 QQ 列表 |
| `raw_message` | `std::string` | 剥离 CQ 码后的原始文本 |
| `plain_text` | `std::string` | 去掉触发前缀后的文本（推荐用于指令匹配） |
| `is_at_bot` | `bool` | 是否 @ 了机器人 |
| `send_reply` | `std::function<void(type, target_id, text)>` | 同步回发消息，**仅限 on_message 内使用** |
| `log` | `std::function<void(text)>` | 输出到界面日志 |
| `send_file` | `std::function<void(type, target_id, path, name)>` | 发送文件，同样仅限同步使用 |
| `async_user_data` / `async_send_reply` / `async_send_file` / `async_log` | C 函数指针 | **线程安全**，后台线程只能使用这一组 |

### 线程安全（重要）

`send_reply` / `log` 是 `std::function`，只在 `on_message` 同步执行期间有效。
**如果在后台线程回发消息，必须使用 `async_*` 系列**，并把 `async_user_data` 作为第一个参数传入：

```cpp
// 在 on_message 里先把回调拷成值（POD + C 函数指针），再交给线程
auto ud      = ctx.async_user_data;
auto send    = ctx.async_send_reply;
auto type    = ctx.message_type;        // std::string 要拷贝
auto target  = (type == "group") ? ctx.group_id : ctx.user_id;

std::thread([ud, send, type, target]() {
    std::this_thread::sleep_for(std::chrono::seconds(3));
    if (send) send(ud, type.c_str(), target, "三秒后的延迟回复");
}).detach();
```

## 三、最小可运行示例

```cpp
#include "plugin_manager.hpp"

class PingPlugin : public IBotPlugin {
public:
    PluginInfo get_info() override {
        PluginInfo info;
        info.name = "Ping 插件";
        info.version = "1.0.0";
        info.author = "you";
        info.description = "收到 ping 回复 pong";
        info.enabled = true;
        return info;
    }

    bool on_load() override { return true; }
    void on_unload() override {}

    bool on_message(const PluginContext& ctx) override {
        if (ctx.plain_text == "ping") {
            ctx.send_reply(ctx.message_type,
                           ctx.message_type == "group" ? ctx.group_id : ctx.user_id,
                           "pong");
            if (ctx.log) ctx.log("[Ping] 已回复一次");
            return true;
        }
        return false;
    }
};

extern "C" __declspec(dllexport) IBotPlugin* create_plugin() { return new PingPlugin(); }
extern "C" __declspec(dllexport) void destroy_plugin(IBotPlugin* p) { delete p; }
```

## 四、工程配置要点

新建 DLL 工程（VS：**动态链接库 DLL**，平台 x64），保持与主程序一致：

| 设置 | 值 | 原因 |
|---|---|---|
| C++ 语言标准 | `stdcpp17` | 与主程序一致 |
| 运行库（Release） | **多线程 `/MT`** | 与主程序一致，避免 CRT 不匹配导致跨 DLL 传 `std::string` 崩溃 |
| 附加包含目录 | `$(SolutionDir)include` | 找到 `plugin_manager.hpp` |
| 字符集 | Unicode | 与主程序一致 |
| 编译选项 | `/utf-8` | 源码含中文注释与字符串 |
| 输出目录 | 主程序的 `plugins\` | 放在一起才能被扫描到 |

命令行编译插件：

```bat
cl /nologo /LD /O2 /EHsc /std:c++17 /utf-8 /D NOMINMAX /D _CRT_SECURE_NO_WARNINGS ^
   /D NDEBUG /D _WINDOWS /D _USRDLL /I include dllmain.cpp /Fe:plugins\demo.dll
```

## 五、实践建议

1. **指令匹配用 `plain_text`**，它已去掉触发前缀，也兼容私聊/群聊。
2. **前缀匹配要带分隔符**，例如只认 `广播 ` 而不是 `广播`，避免把「广播室在哪」误判成指令。
3. **返回 `true` 会阻断 AI**，纯指令类插件应当返回 `true` 以节省 Token；闲聊类插件返回 `false`。
4. **状态持久化**放到运行目录的 `data\` 下，注意用临时文件 + 改名的方式写盘，避免读到半截文件。
5. **异常要自己兜住**：插件内的异常不能抛回主程序，否则会中断消息线程。
6. **调试**：用 `ctx.log(...)` 输出到界面日志面板，比 `printf` 更容易定位（宿主窗口会实时显示）。
